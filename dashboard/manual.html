① 8082/add 提交客户→ ② 接入（写 parser）→ ③ 爬虫运行（定时/手动）→ ④ 数据落 S 盘→ ⑤ 出 AI 报告→ ⑥ 落 S盘/Obsidian/Notion

数据存储服务器本地 + S 盘共享自动

一、怎么提交爬虫任务

1. 打开提交表单

浏览器访问 http://192.168.0.181:8082/add（「客户站点看板」右上角也有「＋ 添加爬虫」按钮）。

表单字段填写说明
客户名 / key英文标识，用作目录名，如 hitachi-hightech（用连字符，别带空格）
站点 URL要爬的根地址。news 模式填新闻列表页；全站爬填英语区根，如 https://www.hitachi-hightech.com/global/en/
备注说明语言/范围（如「只要英语区」）、特殊要求（如 Akamai 防护需真实 Chrome）

2. 提交后发生了什么

  • 服务器把提交存到 onboard/requests/<client>.json，并同步一份到 S 盘队列 S:\_crawler_queue\requests\<client>.json + queue.jsonl。
  • 系统每晚定时器会检查队列，但只对「已接入」的客户自动爬。新客户需先接入（见下一节）。

二、新客户接入（谁负责写爬虫解析器）

关键区分：「提交」≠「接入」。提交只是把客户信息放进队列；要真正能爬，需要 ① 写一个页面解析器（parser）② 在 config/sites.yaml 注册 ③（若站点有 WAF）配好浏览器引擎。这一步是写代码，由绿龙虾（WorkBuddy）完成，火哥确认后生效。

接入要做的事

  1. 绿龙虾读取队列里的提交信息（S 盘 _crawler_queue）。
  2. 写 parser：crawler/parsers/<client>.py（解析列表页/正文）。
  3. 注册配置：config/sites.yaml 加客户段（base_url、list_url、parser、engine、site_priority 等）。
  4. 推代码 → 服务器 git pull。
  5. Akamai/WAF 站点：需 engine: playwright + browser_channel: chrome，服务器已装 google-chrome-stable。
已验证先例：hitachi-hightech 接入流程完整跑通 —— patchright + 真实 Chrome 绕过 Akamai，全站 360 页（含产品页）抓取成功，8082「全站结构」tab 显示。

三、爬虫怎么运行、谁运行

运行主体

爬虫跑在 Ubuntu 服务器 192.168.0.181（项目目录 /opt/client-crawler，虚拟环境 venv）。由 systemd 定时器自动触发，也可手动触发。

自动定时器（当前生效配置）

定时器时间做什么
client-crawler.timer每月 1 日 09:00全量爬所有已配置客户（news 模式，run_weekly.sh）→ 重建看板 → 写运行状态
crawler-check.timer周一 / 三 / 五 19:00检查 S 盘提交队列 → 对「已接入」且有新提交的客户爬一次 → 重建看板（纯代码，不调 AI）

全站爬取（site 模式）—— 手动触发

全站结构化爬取目前没有定时器，需要时手动跑（约 300-400 页浏览器抓取，耗时约 1 小时）：

ssh theeggsh@192.168.0.181
cd /opt/client-crawler && source venv/bin/activate
S_DRIVE_ROOT=/media/theeggsh/SSD-2/AI-Report python cli.py --client <key> --mode site

后台跑（不占终端）：

nohup python cli.py --client <key> --mode site > /tmp/site_<key>.log 2>&1 &
tail -f /tmp/site_<key>.log

手动跑新闻（news）模式

cd /opt/client-crawler && source venv/bin/activate
python cli.py --client <key>        # 默认 news 模式
注意：site 模式结束时会自动重建看板；news 模式由定时器跑完统一重建。服务器需要 S_DRIVE_ROOT（在 .env 已配）才能把数据同步到 S 盘。

四、爬好的数据在哪、什么格式

数据位置（两处，内容一致）

位置路径谁能访问
服务器本地/opt/client-crawler/data/<client>/site/（全站）或 data/<client>/<日期>.json（新闻）服务器 / SSH
S 盘共享（推荐访问）\\192.168.0.181\AI-Report\<client>\site\局域网所有电脑、Obsidian、绿龙虾
看板http://192.168.0.181:8082/（全站结构 / 每周新闻）团队浏览器

每个客户 site 目录下的文件

文件格式内容
<日期>.jsonJSON（原始全文）{client, base_url, crawled_at, total_pages, sections:{板块:[{url,title,meta_description,text,word_count,section}]}}
<日期>_index.jsonJSON（大纲）板块 → 页数 + 每页 title/url/word_count
<日期>_index.mdMarkdown人读板块大纲
<日期>_ai_report.html / .mdHTML / Markdown绿龙虾生成的三支柱 AI 报告

所有文件都是 UTF-8 明文，任何能读文本的工具（Excel、编辑器、LLM）都能打开。JSON 的 text 字段就是页面正文，url 是来源。

五、谁读数据、怎么出报告

1. 绿龙虾（推荐，WorkBuddy 内置）

绿龙虾的 spider-report skill 把 S 盘 site 数据转成三支柱报告：公司介绍 / 网站产品 / 对 Paid Search 的作用与意义，每条事实带来源 URL，结尾附可执行清单（火哥决策 / KB 增补 / Agent 派发 / 循环回写）。

触发方式（手动）：对绿龙虾说「出报告」+ 客户名（如 hitachi-hightech）。报告落三处：

  • S 盘：\\192.168.0.181\AI-Report\<client>\site\<client>-spider-report-<日期>.html
  • 本地 Obsidian vault：D:\WorkBuddy\Obsidian\<客户文件夹>\
  • Notion：Spider Reports 数据库（按客户+日期幂等更新）

2. 网页版 LLM（备用）

云端网页 LLM 访问不到你的局域网，但它能读文本文件。路径：把 <日期>.json 或 _index.md 上传给网页版 LLM（ChatGPT / Kimi / DeepSeek 等），附三支柱提示词即可复现报告。数据就是标准 JSON + Markdown，任何能读文本的 LLM 都能消费。

3. 在 8082 看报告

「🗂️ 全站结构」tab 里每个客户卡片有 📄 AI 报告 ↗，点击直达最新报告（/ai-report/<client>）。

七、常见问题排查

现象原因 / 处理
8082 没有某个客户看是不是在「🗂️ 全站结构」tab（site 数据在这，不在新闻 tab）；浏览器缓存就 Ctrl+Shift+R 强刷
爬取大量 403 / 0 条站点有 WAF（Akamai 等）→ 需 engine: playwright + browser_channel: chrome，服务器必须装了 google-chrome-stable
报 chrome executable doesn't exist服务器没装真实 Chrome：sudo apt-get install -y google-chrome-stable
数据没同步到 S 盘服务器 S_DRIVE_ROOT 未配（.env）或共享挂载只读
看板显示旧数据看板在爬取结束才重建；手动跑 python dashboard/build.py 立即刷新
定时器没跑systemctl status client-crawler.timer crawler-check.timer 看是否 active
产品页没抓到site 模式加了 site_priority（products/knowledge 优先）；若仍缺，调大 site_max_pages
